# 검증 기록과 한계

## 무엇을 확인한 기록인가

이 문서는 **v1.2.0 전달본의 2026-09-12 작성 환경 검증 기록**을 요약합니다. GitHub 공개 준비 과정에서 모든 앱 테스트를 다시 실행했다는 뜻은 아니며, 사용자 PC의 설치 성공을 대신하지 않습니다. 새 기능 정확도나 투자 수익률을 측정한 기록도 아닙니다.

| 구분 | 당시 완료한 범위 | 결과 |
|---|---|---|
| Thesis 백엔드/API | 새 테스트 63개 | 통과 |
| 기존 Stock Watch | 테스트 70개 | 통과 |
| 가격·시세 핵심 | 테스트 37개 | 통과 |

백엔드 170개는 위 세 개의 서로 다른 완료 그룹을 합산한 수입니다. 전체 백엔드 모음을 실행하다 구버전 `test_filing_risk080.StoreTests.test_two_file_batch_is_atomic_on_failure`에서 시간 초과가 있었습니다. 따라서 **전체 테스트 통과**라고 쓰지 않습니다.

## 실제 외부 동작 검증과 구분

새 v1.2.0의 Next.js 프로덕션 빌드는 작성 환경에서 npm DNS 문제로 완료하지 못했습니다. native Windows 실행, 실제 OpenAI 유료 조사, 실제 기업 SEC 조회는 해당 검증에서 수행하지 않았습니다. 이전 v1.1.x 빌드 성공 로그를 새 v1.2.0의 검증 결과로 가져오지 않습니다.

서로 다른 다섯 모의 업종에 같은 파이프라인을 적용한 테스트는 데이터 처리와 분기 동작을 확인한 것입니다. 다섯 실제 기업의 투자 논리를 정확하게 찾았다는 증거가 아닙니다.

## 직접 재현

저장소 루트의 Windows PowerShell에서 설치를 마친 뒤 실행합니다.

```powershell
$env:PYTHONPATH = Join-Path $PWD "backend"
.\.venv\Scripts\python.exe -m unittest discover -s .\backend\tests -p test_signaldesk.py
.\.venv\Scripts\python.exe -m unittest discover -s .\backend\tests -p test_stock_watch110.py
.\.venv\Scripts\python.exe -m unittest discover -s .\backend\tests -p test_thesis120.py

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build-Frontend.ps1
.\.venv\Scripts\python.exe .\scripts\smoke_local.py
```

각 명령의 결과를 따로 확인합니다. `Build-Frontend.ps1`는 검사기·프론트 테스트, 실제 빌드, 산출물 해시 검사를 실행합니다. smoke 테스트는 자신의 임시 localhost 서버를 사용합니다. 분석 API를 직접 누르는 기능 시연과는 다른 검사입니다.

공개 준비본은 개인 캐시가 없는 새 폴더이므로 과거 분석 결과가 보이지 않는 것이 정상입니다. 시연을 위해 재조사할 때는 비용 동의를 확인합니다. 기존 로컬 원본에서는 저장본을 이용해 시연할 수 있지만 캐시 파일을 GitHub에 올리지는 않습니다.

API 키·캐시·백업을 제외한 소스 참조본으로 새 공개 폴더를 구성한 뒤 프론트 헬퍼 292개와 출력 검사기 단위 테스트 28개를 다시 실행해 통과했습니다. 공개 폴더 복사 도구 자체는 16개 테스트로 허용 파일 복사, 비밀 경로 미열람, 기존 폴더 보존, 버전·내용 불일치 거절, 실패 시 임시 폴더 정리를 확인했습니다.

이 검사는 Linux에서 실행한 로컬·오프라인 검사입니다. 새 앱 프로덕션 빌드, native Windows 준비 스크립트 실행, 실제 AI 분석, 실제 SEC 조회, 사용자 시연 캡처를 수행한 것은 아닙니다. 준비 도구 테스트를 금융 분석 테스트 수에 합산하지 않습니다.
